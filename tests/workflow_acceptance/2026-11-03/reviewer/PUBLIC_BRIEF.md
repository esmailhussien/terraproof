## Execution

1. Use the clean frozen wheel in the new isolated installation. Record version/build and dependency environment. Use public discovery for each source-search request, save complete proposals/ranking, and verify the fixed item is selected. Do not select a new scene based on imagery or pipeline outcomes.
2. Acquire exactly the four native assets listed for that item: `mtl.txt`, `lwir11`/ST_B10, `qa_pixel`/QA_PIXEL, and `qa`/ST_QA. Retain original bytes and SHA256. No other bands, scene, preview, mosaic or temporal mixture. Unsigned asset identity must be preserved; transient anonymous SAS may be obtained by the parent.
3. Preserve a ceiling of536870912 new native-transfer bytes across all three scenes, including retries. Catalog responses do not expose file sizes, so no guaranteed total size is claimed. No HEAD/range/pixel request was made during selection. At execution, anonymous signed HEAD checks for all12 fixed assets are permitted before any download. If their aggregate fits the ceiling, exact per-case byte caps with no retries or substitutions are permitted. Check whole-asset lengths where possible before starting, track actual transferred bytes, reuse exact immutable assets where available, and stop on a budget limitation rather than substitute data.
4. R1 uses its search AOI as workflow AOI. Use quantity `land-surface-temperature`, unit `degree_Celsius`, reject QA bits0,1,2,3,4,5,7, minimum valid fraction0.90, no uncertainty cutoff, and omit `scene_coverage` to test the full-AOI default. This is a modest urban snapshot; QA excludes cloud, cirrus, shadow, snow and water. No seasonal inference is requested.
5. R2 search/acquisition uses the Cape Town urban rectangle. After acquiring that fixed scene, derive a separate diagnostic polygon from the native ST_B10 header affine/CRS around rows0..9 and columns0..9. The public JSON gives exact instructions and a metadata-only approximate polygon. Freeze the native-header-derived AOI before reading any diagnostic-corner pixels. The unchanged acquisition path may automatically read the separate source-search AOI for preflight after scene selection is frozen; these reads cannot influence the selected item, fixed corner window, thresholds or diagnostic polygon. Retain that search-AOI preflight separately. It must include exactly100 native centres inside the grid. Do not rediscover using this corner, do not use an axis-aligned WGS84 rectangle, and do not move the corner after observing QA. Run the same polygon twice: no uncertainty cutoff, then explicit2.0K, each minimum0.90 and full-AOI default. These runs test inference on the fixed acquired scene, not source-search feasibility at the corner.
6. R3 uses the Brisbane search AOI for two otherwise identical workflows: no-cutoff baseline and explicit0.005K cutoff; both minimum0.75 and full-AOI default. This cutoff deliberately tests an explicit requirement below the0.01K ST_QA quantization step; it is not an automatic scientific recommendation or a user-use-case threshold. No source reselection or diagnostic threshold adjustment is permitted.
7. Run every variant through supported native admission/preflight before approval. Retain statuses and diagnostics, even when a later stage cannot run. Use supported engineering self-approval only for variants actually resolved as admissible. Do not bypass an unresolved result merely to force output. For admitted variants, execute and retain output, report, grade and approval record. Approval is unauthenticated and self-declared; `checks-passed` is a numerical engineering grade.
8. Retain exact commands, return codes, stdout/stderr, request/proposal/workflow JSON, admission state before approval, asset inventory/hashes, native headers, derived R2 geometry and centre counts, QA/ST/ST_QA raw AOI histograms, and actual transfer ledger. Capture source-independent count/statistical evidence for subsequent review, but do not use it to alter this experiment.
9. Freeze all outcome files and a hash manifest before reading `SEALED_CRITERIA.json` or `SEALED_CRITERIA.md`. Keep originally attempted outcomes even if later diagnostics or reruns occur. The reviewer will assess the retained results afterward.

The native checks must establish whether each challenge was actually exercised: actual full acquisition/QA usefulness in R1; missing acquisition inside a contained native corner in R2; baseline support and exclusions attributable to the explicit uncertainty requirement in R3. No such source condition is claimed established yet. Source availability, budget/environment limits, and naturally unmet hypotheses must be reported honestly as limitations or unexercised tests.

## Public primary sources and attribution

The [Planetary Computer STAC API](https://planetarycomputer.microsoft.com/api/stac/v1) supplied catalog geometry, acquisition time, cloud, platform, correction level, projection and asset metadata only. Native asset URLs were read from those records, never fetched by this reviewer at selection. Catalog queries were GET `/search` with collection `landsat-c2-l2`, each table bbox, inclusive UTC datetime interval, and limit100. Complete responses are preserved as `phoenix-catalog.json`, `cape-town-catalog.json`, and `brisbane-catalog.json`.

[USGS Collection2 Surface Temperature](https://www.usgs.gov/landsat-missions/landsat-collection-2-surface-temperature) documents scaling native temperature DN by0.00341802 and adding149 to obtain Kelvin, and describes missing-data constraints. [USGS Collection2 Quality Assessment Bands](https://www.usgs.gov/landsat-missions/landsat-collection-2-quality-assessment-bands) documents fill/cloud-related QA_PIXEL flags and ST_QA as pixel temperature uncertainty; catalog ST_QA metadata give signed int16, fill-9999, scale0.01K. These references support source interpretation, not certification of particular output accuracy.

Dataset attribution: Earth Resources Observation and Science (EROS) Center (2020), Landsat8-9 Operational Land Imager/Thermal Infrared Sensor Level-2, Collection2, U.S. Geological Survey, [doi:10.5066/P9OGBGM6](https://doi.org/10.5066/P9OGBGM6). USGS states no restrictions on Landsat products. All reviewer-authored experiment instructions are English.
